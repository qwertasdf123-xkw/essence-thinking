# 产出协议（人机协作思维报告）

本文定义"思考如何变成人类可协作的产物"。当 Consolidate 段后需要向人汇报、或用户要求"出份报告/给团队看"时读取。

## 目录

1. 设计本质
2. 报告分级
3. 完整版模板
4. 简版模板
5. 写作红线
6. 去向与后续

## 1. 设计本质

报告是**让人类协作方加入闭环的接口**（公理 5：谁来验证？——报告就是请人来验证的载体）。
- 读者模型：没时间看全过程的协作者。他们要的是"你怎么想的、依据是什么、哪里可能错、需要我做什么"。
- 反模式：把日志流水贴给人（信息全但无法协作）；只给结论不给依据（无法推敲，违反"事实是一切"）。
- 报告的每一节都对应 ESSENCE 的一段产物——写报告不是额外工作，是把已有产物按读者视角重排。

## 2. 报告分级

| 级别 | 触发 | 内容 | 篇幅 |
|---|---|---|---|
| **简版** | 日常同步、单任务收尾 | 结论 + 依据 + 风险 | ≤半页 |
| **完整版** | 架构决策、对外汇报、复盘 | 全文（见模板） | 1~3 页 |
| **正式文档** | 需要分发/存档 | 委托 docx/kimi-pdf 等 skill 排版 | 不限 |

## 3. 完整版模板

```markdown
# 思维报告：<主题> · <日期>

## 一、结论
<一句话结论 + 置信度（高/中/低）>

## 二、本质层级链（怎么想到的）
L1：<现象层本质> — 依据：<事实锚点>
L2：<更基本的关系> — 依据：<事实锚点>
L3：（如有）…
→ 行动含义：<因此应该做什么>

## 三、辩证取舍（为什么这么选）
| 方案 | 优势 | 劣势 | 取舍 |
（必须至少两个候选；只写一个方案等于没做取舍）

## 四、闭环自查
输入✓ 变换✓ 产出✓ 验证与沉淀✓（缺哪环写明怎么补）

## 五、风险与待推敲
<哪里最可能错 + 欢迎攻击的具体点>

## 六、需要协作方做什么
<明确的 1~3 个请求：确认/补充信息/做决策>
```

## 4. 简版模板

```markdown
**结论**：<一句话>（置信度：<高/中/低>）
**依据**：<L1 本质 + 事实锚点>
**风险**：<最可能错的一点>
**需要你做**：<一个具体动作>
```

## 5. 写作红线

- 每个判断后面必须有事实锚点（路径、数据、观察），没有锚点的判断降级为"假设"并标注。
- 第五节"风险与待推敲"禁止为空——报告的可信度恰恰由主动暴露的弱点决定（辩证取舍的 outward 形式）。
- 不给协作方出选择题时不附推荐项；给选择题时必须附推荐 + 理由（公理 2：选型必有类比依据）。
- 篇幅服从读者时间，不服从内容多少——放不下的进 `.essence/reports/<主题>-附录.md`，正文只留链接。

## 6. 去向与后续

- 存 `.essence/reports/`，snapshot 的"下一步"区引用最新一份。
- 协作方的反馈（确认/质疑/新信息）回流：质疑进 inbox，新信息进 Explore——报告是双向接口，不是终点。
- 报告本身不沉淀为模式；**报告引出的修订结论**才走 Evolve 段正常沉淀。
