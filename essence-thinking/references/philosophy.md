## 1. 共性抽象

机制：具体知识 → 理解其架构 → 把握整体关系（框架图谱）→ 识别共性 → 按共性批量掌握相关可复用知识。

操作要点：
- 学新东西时先问"它的架构图长什么样"，而不是"它有哪些功能"。
- 共性总是表述为**关系**："A 是 B 的缓存"、"X 与 Y 通过 Z 解耦"。功能列表不是共性。
- 找到共性后，主动寻找共享该共性的其他知识，一次性纳入掌握（复用学习成本）。

示例：理解了"消息队列 = 生产/消费关系的解耦层"后，Kafka、RabbitMQ、EventBridge 的差异只是该共性上的特性参数（吞吐、投递语义、顺序性），可按共性一并掌握。

## 2. 设计思维

架构演变公式：**新架构 = 大方向 × 技术组合**，通过三条途径收敛到逻辑最优解：
- **类比对比**：从已知架构借结构。"这个系统像不像操作系统里的分页？像不像出版行业的编辑-校对分离？"
- **本质与原理**：该技术解决的根本矛盾是什么？（如：副本解决的是可用性与一致性的矛盾）
- **特性分析**：该技术的边界特性是什么？在什么规模/场景下特性反转？

操作要点：做选型时强制输出三栏表：候选方案｜类比来源｜本质矛盾｜特性边界。

## 3. 分层本质

逻辑思维的对象是**关系**。逐层下钻的标准问法：
- 第一层：当前现象中，哪些事物之间存在什么关系？哪个关系是决定性的？
- 第二层：这个关系本身是由什么更基本的关系构成的？
- 第三层及以后：继续追问，直到结论不再改变行动方案（边际收益为零即停）。

产出格式（本质层级链）：
```
L1: <现象层本质：决定性关系>
L2: <构成 L1 的更基本关系>
L3: <构成 L2 的更基本关系>
→ 行动含义：因此应该 <行动>
```
注意：本质必须可证伪——"如果我理解的这个关系是错的，哪个现象会不一样？"

## 4. 思维进化

- 灵感是思维过程的副产品：先把材料在脑中（或纸上）铺开得足够大，模式会自己浮现；不要直接憋结论。
- 永远从事物本身出发：每个判断都要能指回一个具体的观察、文档、数据或代码行。
- 进化是即时的：本次思考中发现上一阶段的框架不够用，就当场修订框架并记录（写入 evolution.md 的修订历史），不等到"以后"。

## 5. 拼装闭环

- 组件的价值不在其功能，而在它处于闭环中的位置。同一个 wiki：按"存储"主线拼装 → 知识库；按"关联"主线拼装 → 思维过程引擎。
- 检验闭环的四个问题（闭环判据）：输入是什么？经过哪些本质变换？产出什么？验证与沉淀在哪？
- 练习：拿到一组组件，强制给出两种不同主线的拼法，比较两个闭环各自"断在哪"。

## 6. 公理冲突时的裁决顺序

1. 公理 4 最高优先：从事物本身出发——任何公理的应用若与观察到的事实冲突，以事实为准并当场进化框架。
2. 公理 3 次之：结论必须落到"关系"层面才算数。
3. 公理 5 约束产出形态：任何方案必须能闭合。
4. 公理 2 约束设计过程：选型必须有类比与本质依据。
5. 公理 1 约束知识复用：能按共性批量解决的，不做单点重复。
