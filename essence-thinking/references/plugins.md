# 软约束插件化规范

本文定义"什么留本体、什么进插件"的判定标准与插件接口。当发现新约束、准备给 P0 插件开工、或判断某规则该不该进 SKILL.md 时读取。

## 目录

1. 判定标准（一句话）
2. 本体与插件的职责边界

4. 当前插件清单（P0 已实现 / P1 / P2 摘要）

## 1. 判定标准（一句话）

**改它不需要动 SKILL.md 的，就是插件；需要动 SKILL.md 的，才是本体。**

## 2. 本体与插件的职责边界

| 留本体（协议骨架） | 进插件（软约束/特性） |
|---|---|
| 五大公理、元原则 | 预算具体数值与档位 |
| ESSENCE 七段流程与顺序 | 压缩检查清单的执行细节 |
| 思维质量红线 | 报告模板的格式细节 |
| 标准产物格式（接口） | 发布流程、打包校验 |
| 闭环判据四问 | 具体场景的检索源（如 skills 目录扫描路径） |
| 加载协议（L0→L3 层级概念） | 每级的具体 token 数 |

判例：
- "必须先读 snapshot 再动手" → 本体（改的是行为顺序）。
- "snapshot 预算 ≤500 tok" → 插件（数值可调）。
- "委托后必须回收验证" → 本体；"回收时调用 X 脚本" → 插件。

## 3. 插件接口约定

```
plugins/<场景>/
├── PLUGIN.md      # 必需：触发条件 + 声明的输入输出 + 预算声明
└── scripts/       # 可选：可执行实现
```

PLUGIN.md 最小内容：

```markdown
---
name: <插件名>
triggers: <什么时机触发（如"总预算达80%"、"每轮Evolve后"）>
---
# <插件名>
## 输入 <消费什么>
## 输出 <产出什么，写到哪>
## 预算 <自身加载与运行的上下文成本上限>
## 与本体关系 <依赖 SKILL.md 的哪条协议；本体没有它是否仍完整>
```

加载规则（与 wiki 协议同构）：路由层按 triggers 命中才加载 PLUGIN.md；scripts 不读直接执行；同时激活插件 ≤3 个。

## 5. 插件的进化与回检

- 插件用满 3 次做接入评估（routing.md §6 三条护栏同样适用）。
- 插件失效不打 deprecated 删除，标记 + 记录失效场景——与模式库同规则。
- 插件数量与索引本身是上下文成本：每新增一个插件，问一次"它省掉的思考 > 它占掉的索引吗"。
