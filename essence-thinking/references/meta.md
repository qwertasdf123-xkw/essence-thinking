# 元体系（元原则 / 元逻辑 / 元方法的闭环）

本文定义 essence-thinking 的分层元结构及各层之间的闭环箭头。当需要修订本体深层结构、判断"这条规则该放在哪一层"、或研究 skill 自举机制时读取。

## 目录

1. 五层结构
2. 元逻辑显式清单
3. 层间闭环（自下而上修订 + 自上而下指导）
4. 修订的稳定性梯度
5. 判定：新规则放哪层

## 1. 五层结构

```
L0 事实层   —— 一切判断的锚点（观察/文档/数据/代码行）。"事实是一切"。
L1 元原则   —— 裁决准则：事实是一切、辩证取舍。冲突时它比公理先说话。
L2 元逻辑   —— 推理规则：如何下钻、归纳、对比、取舍、验证（见 §2）。
L3 方法层   —— 元逻辑的编排实例：ESSENCE 七段循环、加载协议 L0→L3。
L4 产物层   —— 方法产出的标准格式：本质卡片、层级链、辩证表、闭环方案、思维报告。
```

依赖方向：L4 依赖 L3，L3 依赖 L2，L2 受 L1 裁决，L1 受 L0 检验。**上层不依赖下层的内容，只依赖下层的规则**——这就是"元"的定义：关于下一层"怎么用"的规则，而不是下一层"是什么"的内容。

类比：编程语言自举（用语言自身写编译器）——essence-thinking 用自己的元逻辑审查和改进自己的架构，但修订必须由事实层证据驱动。

## 2. 元逻辑显式清单（此前隐含在公理中，此处显式命名）

| 元逻辑 | 规则一句话 | 出处 |
|---|---|---|
| 下钻 | 每个结论继续问"它的本质是什么"，直到不再改变行动 | 公理 3 |
| 归纳 | 共性总是表述为关系，不是功能清单 | 公理 1 |
| 类比 | 选型必须能指认一个已知结构作为类比来源 | 公理 2 |
| 取舍 | 先正评再红队，结论必附保留/放弃清单 | 元原则·辩证取舍 |
| 验证 | 强度 ∝ 推翻代价 × 新颖度：继承旧思路的做链追溯+抽样，全新的做全量红队；每个本质必须可证伪 | 公理 3/4 |
| 闭合 | 四问闭环判据缺一即补 | 公理 5 |
| 外化 | 上下文是缓存，状态必须落盘才可复用 | wiki 层设计 |
| 延迟 | 捕获与处理分离，批量在停顿点消费 | side-channel |

新增元逻辑的途径只有一条：从任务产物中提炼（公理 1），由事实层验证（公理 4），经辩证取舍（元原则）后升格——不允许凭空新增。

## 3. 层间闭环

**自下而上（修订箭头）**：
```
L4 产物 ──Evolve 沉淀──→ 模式/补丁
模式/补丁 ──批量应用──→ L3 方法修订（self-evolve.md）
L3 修订若反复出现同类 ──升格──→ L2 元逻辑增补
L2 增补若与既有元逻辑冲突 ──交由──→ L1 元原则裁决
任何层与 L0 事实冲突 ──当场推翻并记录（公理 4，最高优先）
```

**自上而下（指导箭头）**：每轮新任务从 L1/L2 出发（读 snapshot 与模式库），用 L3 方法执行，产出 L4 产物——下一轮修订的原料。

两个箭头构成闭环：**用得越多，下层证据越多，上层修订越准；上层越准，下一轮产出质量越高。** 这就是"越思考越强"的结构化解释。

## 4. 修订的稳定性梯度

越深的层，修订门槛越高：

| 层 | 修订门槛 |
|---|---|
| L4 产物格式 | 单个任务中验证即可改 |
| L3 方法 | ≥3 个任务反复印证（self-evolve.md 的补丁标准） |
| L2 元逻辑 | ≥2 个不同领域任务印证 + 一次红队 + 不与其他元逻辑冲突 |
| L1 元原则 | 几乎不改；改意味着框架换代，记 evolution.md 大版本并回滚预案 |
| L0 事实 | 不可"修订"——只增观察；推翻的是判断，不是事实 |

## 5. 判定：新规则放哪层

- "什么是对的" → L1 元原则
- "该怎么推理" → L2 元逻辑
- "先做什么后做什么" → L3 方法
- "输出长什么样" → L4 产物
- "做到什么程度算数"的具体数值 → 插件（plugins.md）

判不出来时，默认放低的层（L4/插件）——放错了下层证据会把它顶上来，放高了错误会传染所有下层（公理 5：拿掉哪一环会断，高危层断的环最多）。
