# 自进化体系详规

本文定义 `.essence/` 进化库的数据结构、写入时机与能力叠加机制。当需要手动整理进化库、批量复盘、或迁移进化库时读取。

## 目录

1. 目录结构与文件职责
2. 写入时机
3. 模式条目格式
4. 能力叠加机制（越用越强）
5. 日志格式
6. 定期进化（可选强化）

## 1. 目录结构与文件职责

```
<工作区>/.essence/
├── patterns.md      # 共性模式库：唯一事实源，所有复用从这里开始
├── logs/            # 每次 ESSENCE 循环的完整思维记录
│   └── YYYY-MM-DD-<slug>.md
├── evolution.md     # 进化总账：模式数、修订历史、能力叠加记录
└── wiki/            # 知识 wiki 层（见 wiki.md）
    ├── inbox/
    ├── moc/
    └── snapshots/
```

- `patterns.md` 只增不改（模式过时打 `[deprecated]` 标记，不删除，保留进化痕迹——公理 4）。
- `logs/` 每循环一条，文件由 `scripts/et_log.py` 创建。
- `evolution.md` 由脚本自动更新计数与历史，人工补充"为什么修订框架"的说明。

## 2. 写入时机

- **每次完整跑完 ESSENCE 循环**：必须调用 `scripts/et_log.py` 写日志。
- **提炼出新共性时**：追加模式条目到 `patterns.md`。判断标准：这条认识下次遇到类似任务能省掉至少一步思考；且能表述为"关系"。
- **框架被事实推翻时**：在 `evolution.md` 追加修订记录（原框架 → 新框架 → 触发修订的观察）。
- **任务开始时**：先读 `patterns.md` 与 snapshot，把命中模式作为思维起点（Extract 段的输入之一）。

## 3. 模式条目格式

```markdown
### <模式名>｜来源：<任务/slug>｜提出：<YYYY-MM-DD>
- 适用条件：<什么情况能用>
- 本质：<一句话，必须含关系>
- 复用方式：<下次怎么用，具体动作>
- 状态：active / deprecated
```

示例：

```markdown
### 解耦层模式｜来源：2026-10-21-queue-design｜提出：2026-10-21
- 适用条件：两个模块更新频率不同或需要异步协作
- 本质：解耦层是"生产-消费"关系的缓冲，把时序耦合变为契约耦合
- 复用方式：遇到协作瓶颈先问"生产者和消费者之间缺不缺一个契约层"
- 状态：active
```

## 4. 能力叠加机制

正循环：**读模式 → 用模式 → 检验模式 → 强化或修订模式**。

- 命中且奏效：在日志中记 `模式命中：<模式名>`，累计命中计入 evolution.md。
- 命中但失灵：不删，打 `deprecated` 并在条目下补一行 `失效场景：<观察>`——失效本身是进化原料。
- 未命中但事后发现共性：补录新模式。

能力叠加判据：第 N 次类似任务消耗的推理步骤 < 第 1 次，即视为能力已叠加成功。

## 5. 日志格式

```markdown
# 思维日志：<任务名>
- 日期：<YYYY-MM-DD>
- 触发：<用户请求摘要>
- 阶段轨迹：Explore → Strip → Stack → ...（记录实际执行了哪些段）
- 本质层级链：<L1→L2→L3 摘要>
- 红队判定：PASS / REVISE / REJECT
- 模式命中：<模式名列表，无则写"无">
- 新模式：<条目数 + 标题，无则写"无">
- 框架修订：<有/无 + 一句话>
```

## 6. 定期进化（可选强化）

当用户要求"整理进化库"或"复盘最近 N 次"时：
1. 读最近 N 条日志，聚类反复出现的本质层级链。
2. 把多个任务共享的 L2/L3 共性提升为"元模式"，单独收录（元模式 = 跨领域的共性，公理 1 的最高形态）。
3. 更新 evolution.md：模式总数、active 数、元模式数、本月框架修订次数。
